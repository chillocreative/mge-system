# Monthly Progress Report — Design Spec

**Date:** 2026-09-17
**Status:** Approved 2026-09-17 (decisions in §11 confirmed by the user)
**Reference document:** `Monthly Report Jan 2026_ No.3_Final.pdf` (JPS Johor, RTB Sg. Muar / Pintasan Tg. Olak, 48 pages)

---

## 1. Goal

Generate a client-ready Monthly Progress Report (MPR) for a project from data already
in MGE-PMS, let the user review and edit every section in the browser, and export it
as **PDF** (final, JPS layout) and **DOCX** (editable in Microsoft Word for additions
the system does not cover).

Non-goals: replacing MS Project (CPM scheduling), automatic drone photo capture,
multi-language output (report is English, as the reference).

## 3. Data model

All new tables carry `created_by`, `timestamps`, and cascade on project delete.

### 3.1 Contract Particulars (section 1.1)

Extend `project_contracts` (one contract already carries title/contract_no/value/dates):

```
contract_sum            decimal(15,2)   nullable   -- "Contract Sum" (contract_value stays for internal use)
performance_bond_amount decimal(15,2)   nullable   -- WJP / Performance Guarantee
duration_months         unsignedSmallInt nullable
dlp_months              unsignedSmallInt nullable
lad_per_day             decimal(12,2)   nullable   -- reference shows this under "DLP" but it is LAD
possession_date         date            nullable
completion_date         date            nullable   -- contractual
dlp_start_date          date            nullable
dlp_end_date            date            nullable
cidb_registration       string          nullable   -- "TBA" allowed
insurances              json            nullable   -- [{type, insurer, policy_no, period_from, period_to, maintenance_from, maintenance_to}]
```

Amount-in-words ("Two Hundred Eighty-Eight Million Ringgit Only") is generated by a
helper, not stored.

### 3.2 Project Parties (section 1.2, cover, signatories)

```
project_parties
  id, project_id, role enum(owner, superintending_officer, so_representative,
      district_engineer, quantity_surveyor, consultant, contractor, other),
  role_label string nullable (free text when role=other),
  company_name string, address text nullable, logo_path string nullable, sort_order

project_party_contacts
  id, project_party_id, name, designation nullable, phone nullable, email nullable, sort_order
```

Logos are uploaded once per party (JPS wave, RiZ, MGE) and reused in headers.

### 3.3 Organisation chart (1.4)

Extend `project_members`: `designation string nullable`, `reports_to_user_id nullable`,
`org_sort smallint`. The chart is rendered from this tree; "TBA" boxes are plain rows
with `user_id null` + `placeholder_name`.

### 3.4 Progress periods and schedule baseline (2.1, 2.2, 2.4)

```
project_schedule_baselines           -- the CPM plan, one row per month
  id, project_id, month date (first day), scheduled_physical_pct decimal(5,2),
  scheduled_financial_amount decimal(15,2) nullable, scheduled_financial_pct decimal(5,2) nullable,
  source enum(manual, import), imported_at

project_progress_periods             -- one row per report period (cutoff date)
  id, project_id, period_no smallint, period_start date, period_end date,
  planning_days_completion int nullable,
  physical_scheduled_pct, physical_actual_pct,
  financial_scheduled_pct, financial_actual_pct, financial_actual_amount decimal(15,2),
  ahead_delay_days int, physical_status string ("ON TRACK","AHEAD","DELAY"),
  financial_status string ("No Claim","IPC No. 3"), notes text
```

Scheduled values default from the baseline row for `period_end`'s month; actual values
are entered (or pulled from the latest certified claim for financial). Variance and
ahead/delay days are computed: `variance = actual − scheduled`;
`ahead_delay_days = round(variance / 100 × planning_days_completion)` unless overridden.

S-curve series: X = baseline months; blue = `scheduled_physical_pct`; orange =
`physical_actual_pct` for periods that exist. Financial curve uses amounts.

### 3.5 Claims (2.3)

Extend `project_invoices` (claims): `wjp_current`, `wjp_cumulative`,
`certified_current`, `certified_cumulative` decimal(15,2) nullable, `evaluation_date`
date nullable. `claim_number`, `payment_cert_date`, `amount` already exist.

### 3.6 Work programme import (2.5)

```
project_programme_versions
  id, project_id, label ("Draft CPM Rev 0"), status_date date, source_file_path,
  source_type enum(xlsx, msproject_xml), gantt_file_path nullable (PDF/PNG pages), imported_by

programme_activities
  id, version_id, seq int, outline_level tinyint, name, duration_days int,
  start date, finish date, actual_pct decimal(5,2), plan_pct decimal(5,2), is_summary bool
```

Import paths:
1. **XLSX** (primary): the user exports the MS Project view to Excel. Mapping screen
   lets them pick columns for Name / Duration / Start / Finish / Actual % / Plan %.
   Indentation level is inferred from leading spaces in Name or an optional
   "Outline Level" column.
2. **MS Project XML (MSPDI)**: parsed directly (`Task/Name, Duration, Start, Finish,
   PercentComplete, OutlineLevel`). Plan % is taken from a mapped custom field or left
   blank.

Section 2.5 in the report = activity table (all rows, small font, landscape) followed by
the uploaded Gantt pages as full-page images. Rendering a Gantt from data is out of scope.

### 3.7 Delay notices (2.6)

```
project_delay_notices
  id, project_id, title, issue, correspondence_id nullable, reg_number string,
  submitted_date date, submitted_via string ("email"), reply_date date nullable,
  status enum(open, close), impact text, sort_order
```
`duration_days` computed = reply_date (or period_end) − submitted_date.

### 3.8 Correspondence groups (3.1, 3.2)

Add `report_group` string nullable to `correspondence_types` and seed/extend codes:
`adm` (Main Issues), `ma` (Material Approval), `mos` (Method of Statement), `rfi`,
`ncr`. Existing `rfa`, `rfwi` get `report_group = null` (not in the report) unless the
user maps them. Summary counts per group:
- Accumulative = all records to period_end
- Previous = records up to previous period_end
- Current = records dated within the period
- Open/Closed by `status` and close dates.

### 3.9 Testing & commissioning (3.4)

```
project_tests
  id, project_id, ref_no, name, test_date, result string, remarks text,
  attachment_id nullable, sort_order
```

### 3.10 Drawings (3.6)

Add `is_tender boolean default false` to `drawings`. Report lists `drawing_no` + `title`
ordered by `drawing_no`.

### 3.11 Site log categories (4.1, 4.2)

```
project_resource_categories
  id, project_id, kind enum(worker, machinery), group string
      (worker: "Management Team" | "Tradesman"; machinery: null), name, sort_order, active
```
- `site_log_workers.worker_type` and `site_log_machinery.machinery_type` become free
  strings validated against the project's category list (fallback to the current global
  defaults when the project has none). Existing rows are untouched.
- Report matrices: columns = every calendar day in the period (weekends/holidays shaded
  like the reference), rows = categories, cell = quantity from that day's site log(s),
  `-` when no log. Totals row.

### 3.12 Weather chart (4.3)

Derived from `site_log_weather_events` (`rain_start` / `rain_stop` times). Per day: 24
sectors; a sector is filled when it lies inside a rain interval. Totals: days in period,
raining days, raining hours (sum of intervals, capped at day boundaries). No schema change.

### 3.13 Report images (1.3, 5.0)

```
report_images
  id, project_id, section enum(location, site_access, progress_key_plan, progress),
  label string nullable ("Aerial 1", "Overall Site View"), period_id nullable,
  file_path, caption nullable, sort_order, taken_on date nullable
```
Progress pairs are matched by `label`: previous = image with `period_id` of the
previous report, current = this period. Missing side renders an empty cell.

### 3.14 The report itself

```
monthly_reports
  id, project_id, report_no smallint, title ("Monthly Progress Report No.3"),
  period_id -> project_progress_periods, month_label ("January 2026"),
  evaluation_date date nullable, status enum(draft, final),
  signatories json  -- [{slot: prepared|verified|accepted, name, designation, company}]
  options json      -- {include_sections: [...], landscape_sections: [...]}
  generated_at, generated_by, finalised_at, finalised_by

monthly_report_sections
  id, report_id, key ("1.1"), title, sort_order, include bool,
  data json          -- snapshot produced by the builder (tables, values, image refs)
  overrides json     -- user edits on top of data (same shape, sparse)
  notes text         -- free text appended under the section (editable)
  regenerated_at

monthly_report_assets
  id, report_id, kind enum(chart_physical_scurve, chart_financial_scurve, chart_weather,
      gantt_page, custom), file_path, sort_order
```

Design rule: **`data` is machine-owned, `overrides` is user-owned.** "Regenerate" replaces
`data` and keeps `overrides`; the editor shows a diff badge when a regenerated value
differs from an override so the user can accept or keep theirs. Finalising a report locks
edits and freezes assets.

## 4. Generation engine (backend)

```
app/Services/MonthlyReport/
  MonthlyReportService        create / regenerate / finalise / duplicateFromPrevious
  ReportContext               project, contract, period, previousPeriod, parties, options
  Sections/                   one builder per key, all implement SectionBuilder
    SectionBuilder            build(ReportContext): array  (returns the `data` JSON)
    ProjectInformationBuilder ("1.1"), ContractCorrespondenceBuilder ("1.2"), ...
  Charts/
    SCurveSvg                 server-side SVG (PDF fallback)
    WeatherClockSvg
  Export/
    PdfExporter               DomPDF, portrait + landscape chunks merged with FPDI
    DocxExporter              PHPWord
  Import/
    ProgrammeXlsxImporter, ProgrammeMspdiImporter
```

Builders read only; they never write to domain tables. `regenerate(section)` re-runs one
builder. Every builder returns a versioned shape (`{schema: 1, ...}`) so exporters can
evolve.

Chart images: the editor page renders S-curves and the weather chart with Chart.js /
SVG and uploads PNG snapshots to `monthly_report_assets` on **Refresh charts** (and
automatically before export if missing). PDF export falls back to server-side SVG when
no snapshot exists; DOCX requires PNG (PHPWord has no SVG support), so export blocks
with a clear message until charts are refreshed. Rationale: no dependency on GD/Imagick
on the cPanel host (production PHP already lacks `fileinfo`).

## 5. Export

### 5.1 PDF (DomPDF, already installed)
- Blade `resources/views/pdf/monthly-report/*.blade.php`, one partial per section.
- Page master: A4, header = client logo left / project title + contract no centre /
  MGE logo right, footer = "Page X of Y" + "Monthly Progress Report No.N" (DomPDF
  `page_text`).
- Mixed orientation: portrait for narrative sections, landscape for org chart, IPC
  table, S-curves, activity table, matrices. DomPDF cannot mix orientations in one
  document, so the exporter renders chunks and merges them with `setasign/fpdi` +
  `setasign/fpdf` (pure PHP, no extensions). Gantt PDF pages uploaded by the user are
  appended the same way. "Page X of Y" is stamped during merge so numbering is global.
- Images are downscaled on upload (GD when available, else stored as-is with a size
  warning) to keep a 48-page report under DomPDF's memory limit.

### 5.2 DOCX (phpoffice/phpword, new dependency — vendor is committed, deploy has no composer step)
- Real Word sections: portrait/landscape section breaks, header/footer with logos and
  `PAGE`/`NUMPAGES` fields, a TOC field (Word refreshes it on open; the user is told
  to press F9).
- Tables use the reference's green header shading (`D9EAD3`), 1pt borders, repeating
  header rows; long tables split across pages.
- Images inserted from the stored PNG snapshots and report images.
- Everything is plain Word content — no content controls or macros — so the user can
  edit freely.

Both exporters consume the same merged view: `data` ⊕ `overrides` ⊕ `notes`.

Permissions: `reports.view` (open/export), `reports.manage` (create/edit/finalise),
granted to Admin & HR and Projects roles; supporting data uses existing `projects.edit`.

## 7. Frontend

Menu: **Projects → Monthly Reports** (list across projects, filter by project/status).

1. **List** — columns: project, report no, period, status, generated, actions
   (open, PDF, DOCX, duplicate).
2. **New report** — project, report no (auto = last + 1), period start/end (default:
   16th of previous month → 15th of this month, editable), "copy static sections from
   previous report" toggle (parties, org chart, location, tender drawings, signatories).
3. **Editor** — two-pane: left = section list with include toggles and status badges
   (auto / edited / needs charts), right = the selected section:
   - Value sections (1.1, 2.1): form fields pre-filled; edits become overrides.
   - Table sections (1.2, 2.3, 2.6, 3.x, 4.x): inline-editable grid, add/remove/reorder rows.
   - Chart sections (2.2, 2.4, 4.3): live chart + **Refresh charts** button.
   - Image sections (1.3, 5.0): upload, label, caption, drag-to-order, Previous/Current pairing.
   - Every section: "Regenerate from system", "Notes" textarea, diff badges.
   - Header bar: report status, Save, Export PDF, Export DOCX, Finalise.
4. **Project tabs** gain a **Report Data** tab grouping the supporting screens
   (Contract Particulars, Parties, Org Chart, Progress & Baseline, Work Programme,
   Delay Notices, Tests, Resource Categories, Report Images) so data lives with the
   project and the report only snapshots it.

## 9. Testing

- Unit: every SectionBuilder against a seeded project (fixtures for periods, logs,
  correspondence); amount-in-words helper; weather interval maths (overnight rain,
  missing `rain_stop`, multiple intervals); matrix day columns incl. month boundaries.
- Feature: report create → regenerate → override → export PDF (assert page count and
  section headings via text extraction) → export DOCX (assert ZIP contains
  `word/document.xml` with section titles).
- Importers: XLSX with/without outline column, MSPDI sample file, malformed file → 422.
- Permission/IDOR: report of project B not reachable via project A routes.
- Local demo seeder (git-excluded, like the existing ones) that fills all supporting
  data for PR4829 so the editor can be reviewed end-to-end.

## 10. Risks and mitigations

| Risk | Mitigation |
|---|---|
| DomPDF memory/time on 48 pages with ~30 photos | Downscale on upload; render per-chunk; `set_time_limit` on export; stream file |
| Production PHP lacks `fileinfo` (known) and possibly GD | No MIME sniffing; charts rendered client-side; GD used only opportunistically |
| Mixed orientation in one PDF | FPDI merge of chunks (pure PHP) |
| Activity table (450 rows) in DOCX/PDF | Repeating header rows, 7pt font, landscape; paginated API for the editor |
| Users editing generated numbers then regenerating | `data` vs `overrides` split + diff badges; finalise locks |
| Report categories differ per client (JPS vs others) | Section keys/titles stored per report; `options.include_sections`; per-project resource categories |

## 11. Decisions (confirmed 2026-09-17)

1. **Period convention is per project**: `projects.report_cutoff_day` (1–28, default 15).
   A report period runs from `cutoff_day + 1` of the previous month to `cutoff_day` of
   the report month; the new-report screen pre-fills from this and stays editable.
2. **Contract particulars live on the Contract.** `project_contracts.is_main` marks the
   contract the report reads; exactly one main contract per project (enforced in the
   service when set).
3. **Correspondence types `adm`, `ma`, `mos` are real types** so reference numbers are
   generated by the existing register.
4. **Site-log categories are per-project lists**; the current global enum is the default
   template copied into a project on first use.
5. **Gantt is uploaded** from MS Project as PDF pages, never drawn by the system.
6. **DOCX** mirrors the PDF layout but is not pixel-identical; Word refreshes the TOC on open.
7. New Composer packages `phpoffice/phpword`, `setasign/fpdi`, `setasign/fpdf` are
   committed to `vendor/`.
8. **Delivery order**: Phase A (data foundation) and Phase B (report core + editor +
   portrait PDF) first; C (charts/landscape), D (Word), E (programme import), F (polish)
   follow.
